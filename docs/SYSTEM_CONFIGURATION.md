# دليل الإعدادات المركزية ولوحة المطور

## إنشاء المطور والوصول

نفّذ من مجلد المشروع:

```powershell
php artisan developer:create
```

يسأل الأمر تفاعليًا عن الاسم والبريد وكلمة المرور وتأكيدها. لا توجد كلمة مرور ثابتة ولا خيار لتمريرها في سطر الأوامر. الحد الأدنى 12 حرفًا، ولا تُطبع أو تسجل كلمة المرور. الحساب بدور `developer` وصلاحية `manage-system-settings` فقط، دون صلاحيات مالية.

سجل الدخول بالحساب، ثم افتح «إعدادات المطور» أو `http://127.0.0.1:5173/#/developer/settings`. لم يُنشأ حساب مطور فعلي بكلمة مرور يختارها النظام؛ الإنشاء التفاعلي يترك بيانات الدخول لصاحب النظام. حسابات المطور التجريبية محصورة بقاعدة الاختبار.

المدير والموارد البشرية والمراجع ممنوعون من APIs المطور حتى لو زُوّر حقل الصلاحيات. توجد Middleware وسياسة Laravel إضافة إلى حماية الواجهة. المدير لا يستطيع تغيير دور مطور قائم أو تعيين كلمة مروره أو إنشاء دور developer عبر لوحة المستخدمين العادية.

## مجموعات الإعدادات

| المجموعة | الخيارات |
|---|---|
| الهوية | الاسم العربي والإنجليزي، المختصر، الوصف، الشركة المالكة، نص التذييل وحقوق النشر والموقع |
| الشعارات | الرئيسي، القائمة، favicon، الطباعة؛ رفع أو رجوع للافتراضي |
| المظهر | primary/secondary/accent، خلفية وبطاقة ونص فاتح وداكن، النجاح والتحذير والخطأ، خط عربي وإنجليزي من القائمة المعتمدة، الحواف، الوضع، كثافة الجداول، حجم الشعار، قائمة فاتحة/داكنة |
| العرض | locale عربي/إنجليزي، تنسيق التاريخ، الأرقام العربية/اللاتينية، منطقة زمنية صحيحة، صفوف الجداول، منازل عرض المال، SAR |
| المستندات | بادئات مخالصات النهاية والإجازة، وبادئة أرقام السلف التلقائية |
| التقارير | الجهة، A4/Letter، اتجاه طباعة التصفية، إظهار الشعار، التذييل |

العملة مقيدة بـSAR لتجنب إعادة تسمية قيمة مالية دون تحويل حقيقي. التقريب في العرض لا يغير الدقة المحاسبية أو بيانات المعاملات المحفوظة. البادئات الجديدة تخص مستندات جديدة ولا تعيد ترقيم القديم. يمكن إدخال مرجع سلفة يدويًا؛ عند تركه فارغًا يولد بادئة السنة ومعرفًا عشوائيًا فريدًا. الملخصات المالية وقيود العمل لا تقبل إعدادات مطور.

اختيار locale يضبط اتجاه الواجهة ولغة المتصفح وتنسيقات الأرقام والتاريخ. نصوص الأعمال الحالية عربية؛ لم تنفذ ترجمة إنجليزية كاملة. خطوط المتصفح محلية مع بدائل، وmPDF يستخدم خطوطه المدمجة الداعمة للعربية للحفاظ على سلامة المستند عبر الأجهزة. تقارير السلف العريضة تبقى أفقية وتستخدم مقاس الورق المختار.

## الاستخدام والمعاينة

عدل الحقول ثم اضغط «معاينة». يتغير المظهر والعنوان مؤقتًا في الصفحة نفسها، دون حفظ. الإلغاء أو مغادرة لوحة المطور يعيد الهوية المحفوظة. اضغط «حفظ التغييرات» مع السبب لاعتماد القيم، فتظهر في المكونات المرتبطة دون إعادة build. الصفحات المفتوحة الأخرى تقرأ التحديث عند الرجوع للنافذة؛ تحديث الصفحة يحتفظ بالقيم.

استعادة الافتراضي تتطلب كتابة `RESET` وسبب. لا تحذف موظفًا أو سلفة أو تصفية. استيراد JSON يتطلب `RESTORE` وسبب. لا تتجاوز المعاينة فحص الخادم عند الحفظ.

رقم `revision` يمنع جلسة قديمة من الكتابة فوق جلسة حفظت تغييرًا أحدث. عند رسالة تعارض، حدّث الصفحة وأعد المراجعة. الشعارات تحفظ أولًا كأصول مستقلة للمعاينة، ولا تتغير الهوية العامة حتى الحفظ. الأصول القديمة محفوظة ولا تُحذف تلقائيًا.

## التخزين وCache

`system_settings`: id، scope، group، key، value(JSON)، value_type، is_public، is_editable، updated_by، timestamps؛ فهرس unique على scope/key. صف `_revision` داخلي محمي وغير عام.

`system_branding_assets`: UUID، scope، مسار خاص مولد، SHA-256، created_by، timestamps. الرفع 2MB كحد أقصى وأبعاد من 8 إلى 2048 بكسل؛ تعاد الكتابة إلى PNG لإزالة أي محتوى زائد. SVG والتنفيذيات مرفوضة. ملفات الشعارات تؤخذ ضمن النسخ الكاملة، وفحص الاستعادة يتحقق من وجود مراجعها أيضًا.

القيم الافتراضية وRegistry في `config/system.php`؛ الخدمة `SystemSettingsService` تقرأ القيم وتتحقق من التعديلات وتكتب بمعاملة وتدقيق. Cache لمدة 300 ثانية مع مفتاح معزول حسب المشروع وقاعدة البيانات والنطاق، ويُبطل بعد الحفظ الناجح. إذا كان الجدول غير موجود تعمل الافتراضيات. React يستخدم نسخة البدء المركزية/آخر قيم عامة محفوظة عند تعذر API ويعرض تنبيهًا للمستخدم المسجل.

الأسرار لا تدخل الجدول أصلًا: لا DB credentials أو APP_KEY أو SMTP/Redis/storage/API secrets ولا إعدادات الجلسات. حالة الخدمات في اللوحة تعطي نتائج فحص DB/Cache/storage، وحالة إعداد البريد فقط. لا يرسل هذا الفحص رسائل ولا يدعي نجاح SMTP.

## الواجهات

| المسار | الحماية والغرض |
|---|---|
| GET /api/system/public-settings | عام، قيم آمنة فقط |
| GET /api/system/branding/{uuid} | صورة PNG عامة بأسماء مولدة وnosniff |
| GET /api/developer/settings | مطور مخول، القيم والسجل والافتراضيات |
| PUT /api/developer/settings | settings + revision + reason |
| POST /api/developer/settings/reset | revision + reason + confirmation=RESET |
| POST /api/developer/branding/upload | multipart file، لا يعتمد الشعار تلقائيًا |
| GET /api/developer/health | حالات دون بيانات اعتماد |
| GET /api/developer/settings/audit | سجل تغييرات بصفحات |
| GET /api/developer/settings/export | JSON للإعدادات الآمنة فقط |
| POST /api/developer/settings/restore | schema=1 + settings + revision + reason + confirmation=RESTORE |

نسخة JSON تستخدم مراجع شعارات النسخة الحالية. لنقل الهوية إلى تثبيت جديد، ارفع الشعارات هناك أو انقل النسخة الكاملة مع الأصول؛ لا تُقبل مراجع أصول غير موجودة. النسخ الكاملة المشفرة الموجودة تشمل قاعدة الإعدادات وملفاتها، ولا تحتوي JSON الإعدادات على مفاتيح سرية.

## إضافة إعداد جديد

1. عرّفه في `config/system.php` بقيمة افتراضية، نوع، قواعد تحقق، مجموعة، public/editable، وقائمة خيارات إن كانت enum. لا تسجل سرًا أو قاعدة مالية.
2. استهلكه عبر الخدمة في Laravel أو عبر Context في React. عناصر اللوحة تتولد من Registry، فلا تضف منطق حفظ مكررًا.
3. إذا احتاجته الواجهة أثناء أول تحميل، أضف قيمة fallback آمنة في `frontend/src/system/settings.js`؛ تبقى قيمة Registry المرجع بعد تحميل API.
4. أضف اختبار رفض القيم الخاطئة والصلاحيات والحفظ وCache والتأثير المتوقع، ثم شغل اختبارات التراجع.

## التقارير والبريد

هوية PDF وملخص Excel والطباعة وكشوف السلف تأتي من الخدمة. بيانات الحساب وsnapshot التاريخية لا تُكتب مجددًا عند تخصيص الهوية. قالب Laravel Markdown للبريد واسم المرسل يقرآن الهوية عند الإرسال؛ لم تُضف خدمة إرسال أعمال جديدة ولم يُرسل بريد أثناء التطوير.

## التشغيل المحلي

```powershell
php artisan migrate
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/serve-local.ps1 -Port 8000
# داخل frontend
node node_modules/vite/bin/vite.js build --configLoader native
```

مشغل PHP المحلي يضبط upload_tmp_dir داخل `storage/framework/upload-tmp` ويكتب تحذيرات PHP في السجل بدل تلويث JSON. هذا يحل تحذير XAMPP عند عدم قدرة عملية التطوير على الكتابة في مجلد XAMPP المؤقت. لا يعدل php.ini العام، ولا يجعل إعدادات PHP السرية قابلة للتغيير من اللوحة. في الإنتاج استخدم PHP-FPM/Apache مع مجلد رفع قابل للكتابة وإيقاف عرض أخطاء PHP للعميل.
