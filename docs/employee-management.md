# إدارة الموظفين والاستيراد وربط المخالصات

تم التنفيذ على المشروع الحالي في 21 أكتوبر 2026.

تحديث سياسة الراتب: بناءً على طلب المستخدم، أصبح الإدراج الافتراضي لجميع مكونات الراتب في نهاية الخدمة والإجازة والإشعار مفعّلًا. نُفذ أمر `php artisan employees:use-gross-salary` على 1193 موظفًا موجودًا، بعد إنشاء نسخة SQLite احتياطية قبل العملية. لا يغير الأمر المخالصات المحفوظة؛ يجب إعادة اختيار الموظف والحساب لتطبيق الإعدادات الجديدة. نجح 13 اختبارًا مخصصًا للموظفين (149 تحققًا) وبناء الواجهة بعد هذا التحديث.

## نتيجة تحليل المشروع

- الخلفية Laravel 12 وPHP، والمصادقة Sanctum. قاعدة التشغيل المحلية SQLite؛ المخطط يدعم MySQL.
- الواجهة React 19 وVite 8 وTailwind، عربية RTL.
- يوجد أصلًا جدول `employees` مرتبط بـ`contracts` و`salary_components` و`settlements` و`hr_transactions`؛ أُعيد استخدامه.
- توجد أدوار مدير وموارد بشرية ومراجع، وصلاحيات للمعاملات عبر User/Gate.
- توجد خدمات منفصلة لاحتساب الراتب والإجازة ونهاية الخدمة والإشعار، وخدمات للمراجعة والتصدير.
- معاملات `hr_transactions` تحفظ أصلًا نسخ المدخلات والحساب والراتب والموظف، وتاريخ المراجعات. استُخدمت هذه الآلية ولم يُنشأ جدول مخالصات بديل.
- لا توجد جداول شركات أو وحدات تنظيمية مرجعية مناسبة؛ أُضيفت الشركة كنص، واستُخدم حقل القسم الموجود للوحدة التنظيمية.
- لم تتغير معادلات نهاية الخدمة أو استحقاق الإجازة في هذا التطوير. ما تغير هو مصدر بيانات الموظف ومكونات الراتب وقواعد إدراجها.

## قاعدة البيانات

توسعة `employees` بإضافة الشركة والجنسية وآخر تصفية إجازة وتسعة مكونات مالية من نوع `DECIMAL(12,2)` وقواعد الإدراج `salary_inclusion`.

يُعاد استخدام الحقول الحالية بدل تكرارها، وتوفر واجهة API الأسماء البديلة المطلوبة:

| الاسم المطلوب | الحقل الموجود |
|---|---|
| employee_code | employee_number |
| identity_number | national_id_or_iqama |
| organizational_unit | department |
| profession | job_title |
| joining_date | hire_date |
| employment_status | status |

كود الموظف والهوية نصوص. قيد فريد مركب على الشركة وكود الموظف يمنع التكرار داخل الشركة، ويسمح بالكود نفسه في شركة أخرى. الإجمالي يُحسب في الخادم من المكونات؛ لا يُقرأ إجمالي Excel.

الجدول الجديد الوحيد: `employee_imports`، يحفظ المستخدم والملف والنمط والحالة وأعداد الجديد والمحدث والمرفوض والمتجاهل والأوقات. بيانات المعاينة مشفرة بمفتاح التطبيق ومخفية من الردود العامة. تنتهي إتاحتها بعد 24 ساعة، وتُحذف عند نجاح الاستيراد أو بأمر التنظيف المجدول بعد انتهائها، مع بقاء سجل النتائج.

لا يُحذف الموظف فعليًا من نقطة الحذف القديمة؛ يُعطّل مع الإبقاء على المخالصات والعلاقات. التراجع عن الهجرة يرفض إزالة نطاق الشركة إذا وُجدت أكواد مكررة بين شركات مختلفة، حتى لا تضيع هوية هذه السجلات.

## الواجهات وطريقة الاستخدام

1. افتح `http://127.0.0.1:5173/#/employees` وسجّل الدخول بحساب الموارد البشرية أو المدير.
2. اختر «إضافة موظف»، وأدخل البيانات الشخصية والوظيفية ومكونات الراتب وآخر تصفية إجازة.
3. راجع مربعات إدراج كل مكون في أسس نهاية الخدمة والإجازة والإشعار. جميع المكونات مدرجة افتراضيًا لاعتماد الإجمالي؛ ويمكن إلغاء أي مكون صراحةً عند وجود استثناء. كل المكونات تدخل في إجمالي الراتب.
4. من قائمة الموظفين يمكنك البحث والفلترة والعرض والتعديل، أو اختيار «إعداد مخالصة».
5. من الحاسبة يمكن البحث بالكود أو جزء من الاسم أو الهوية. اختيار النتيجة يستدعي ملف الموظف من الخادم، ويعرض بياناته وكل مكونات الراتب وإجماليه.
6. تاريخ المباشرة وآخر تصفية والراتب المحفوظ للعرض داخل المخالصة. تعديل الأصل يتم من إدارة الموظفين، ثم إعادة اختيار الموظف. تاريخ آخر يوم عمل وسبب الإنهاء وأيام راتب شهر التصفية قابلة للتحديد في المخالصة.
7. الحساب والحفظ يعتمدان بيانات الملف في الخادم، حتى لو أُرسلت مبالغ معدلة يدويًا عبر API. إذا تغير الملف بعد الاختيار، يُطلب إعادة اختياره قبل الحفظ.
8. المخالصة مرتبطة بمعرف الموظف، وتحفظ نسخة المدخلات المالية وقواعد الإدراج المستخدمة. تعديل الراتب لاحقًا لا يغير المخالصة القديمة. إعادة حساب معاملة قابلة للتعديل عملية صريحة وفق سير العمل الموجود.

للموظفين القدماء الذين لم يُستكمل ملف راتبهم الجديد، تبقى آلية الحساب اليدوي السابقة متاحة. يُستكمل ملف الموظف من صفحة الإدارة لتفعيل الربط المالي المحمي.

## استيراد XLSX

من «الاستيراد وسجله» حمّل القالب العربي، واملأ الورقة الأولى ثم اختر النمط:

- إضافة الجدد فقط: تجاهل الموجودين دون تغييرهم.
- إضافة الجدد وتحديث الموجودين: المطابقة بالشركة والكود معًا.
- تحديث الموجودين فقط: تجاهل الأكواد غير الموجودة.

الأعمدة المطلوبة: كود الموظف، الاسم، الشركة، تاريخ المباشرة، الأساسي، الحالة. عند تحديث موظف موجود يمكن ترك البيانات الموجودة فارغة للحفاظ عليها؛ الشركة والكود مطلوبان لتحديده. في الموظف الجديد، البدلات الاختيارية الفارغة تساوي صفرًا، والحقول النصية الاختيارية تكون خالية. للمسح الصريح للحقول الاختيارية استخدم نموذج التعديل؛ صفر Excel يمسح مبلغ البدل إلى صفر.

الحالات: `active` أو `inactive` أو `terminated`، وتقبل أيضًا «نشط» و«غير نشط» و«منتهي الخدمة».

التواريخ تقبل `YYYY-MM-DD` أو `DD/MM/YYYY` أو تاريخ Excel الرقمي. المعادلات غير مقبولة. يُنصح بتنسيق الكود والهوية كنص في Excel للحفاظ على الأصفار؛ الأصفار التي أزالها Excel قبل الرفع لا يمكن استعادتها تلقائيًا.

تعرض المعاينة الأعداد والإجراء والأخطاء وأرقام الصفوف، مع صفحات للمعاينة. يمكن تنزيل تقرير XLSX بالأخطاء. وجود أي صف مرفوض يمنع حفظ الملف كله. يتطلب الحفظ ضغط «تأكيد حفظ الاستيراد كاملًا»؛ الرفع والمعاينة لا يكتبان موظفين.

القراءة والتنفيذ بدفعات 200 صف، والحفظ داخل معاملة واحدة؛ تعارض بيانات تغيرت بعد المعاينة يلغي كل الحفظ ويطلب إعادة الرفع. التأكيد لا يمكن تكراره. لا يُحذف أي موظف لعدم وجوده في الملف. قواعد إدراج البدلات للموظفين الموجودين تُحفظ كما هي.

الحدود: XLSX حتى 10 ميجابايت، بيانات مفكوكة حتى 50 ميجابايت، 20000 صف بيانات و50 عمودًا. المعالجة متزامنة بدفعات وليست طابور مهام؛ الملفات الكبيرة جدًا تتطلب موارد ووقت طلب مناسبين للخادم. جرى اختبار 100 موظف وكذلك 205 موظفين لعبور حد الدفعة؛ لم يُنفّذ اختبار تحميل عند الحد الأقصى.

## الصلاحيات والحماية

- المدير والموارد البشرية يديران الملفات والاستيراد. يمكن منح `manage_employees` صراحةً لدور آخر.
- المراجع يرى البيانات الأساسية في دليل الموظفين، ولا يحصل على الهوية أو الراتب أو العقود أو مدخلات الربط. يمكن منحه `view_employee_sensitive` صراحةً.
- الحساب المرتبط بملف راتب يتطلب صلاحية الاطلاع على البيانات الحساسة. مراجعة المعاملات المالية المحفوظة تبقى وفق صلاحيات سير العمل السابق.
- الوصول المباشر إلى العقود ومكونات الرواتب محمي أيضًا. الحقول الجديدة الحساسة والهوية مخفية افتراضيًا من تسلسل نموذج الموظف العام، وتُعاد فقط عبر واجهة الموظفين للمخولين.
- معاينات الاستيراد للمستخدم المنفذ أو المدير فقط. ردود البيانات الحساسة والتنزيلات تمنع التخزين المؤقت.
- لا تُرفع بيانات الملفات إلى خدمة خارجية. تُستخدم PhpSpreadsheet الموجودة ضمن حزمة Maatwebsite Excel المثبتة؛ لم تضف اعتمادًا جديدًا.
- أُغلق التسجيل العام الذي كان يمنح دور الموارد البشرية لأي زائر. إنشاء حساب HR من `/api/auth/register` يتطلب الآن مديرًا مسجلًا. شاشة الدخول الحالية باقية.
- سجل التدقيق يحفظ أحداث إنشاء وتعديل الموظف والاستيراد، ولا ينسخ بيانات الهوية والراتب إلى سجل جديد لهذه العمليات.

## التشغيل والتحقق

طُبقت الهجرة على قاعدة البيانات المحلية الحالية. في بيئة أخرى:

```powershell
php artisan migrate --force
php artisan serve --host=127.0.0.1 --port=8000
```

وفي طرفية أخرى:

```powershell
cd frontend
node node_modules/vite/bin/vite.js --host 127.0.0.1 --configLoader native
```

شغّل Laravel Scheduler دوريًا لتطبيق تنظيف المعاينات المنتهية، أو يدويًا:

```powershell
php artisan employees:prune-imports
```
