# إدارة السلف والتصفيات

الشاشة: `http://127.0.0.1:5173/#/data-management`، من قائمة «إدارة البيانات». تظهر للمدير فقط، وتفرض جميع واجهاتها صلاحية المدير من الخادم أيضًا.

## الإجراءات

- البحث بالمرجع أو اسم الموظف أو رقمه، مع صفحات وفلاتر الأرشيف.
- تعديل مبلغ وملاحظات طلب السلفة غير المصروف وغير المرتبط بحركات أو تصفيات. يعاد إلى «طلب» وتلغى موافقته وخطة أقساطه السابقة لإعادة إعدادها بما يناسب المبلغ الجديد. سجل التدقيق يحفظ قبل التعديل وبعده وسببه.
- إلغاء طلب السلفة غير المصروف. للسلفة المصروفة يستخدم مسار عكس حركات السداد ثم الصرف من شاشة السلف.
- إلغاء التصفية باستخدام خدمة الإلغاء المالي القائمة؛ تحرر الحجوزات وتعكس الخصومات المرحلة. المدفوعة تتطلب مرجع مستند عكس الصرف أو استرداده.
- أرشفة السجلات الملغاة لإخفائها من قائمتي السلف والتصفيات العاديتين. تظهر في إدارة البيانات ويمكن استعادة عرضها. الاستعادة لا تعيد عملية مالية ملغاة إلى العمل.
- حذف المسودات أو البيانات التجريبية/الخاطئة نهائيًا، مع سبب لا يقل عن 10 أحرف، إقرار بأنها بيانات خاطئة، وكتابة `DELETE-ID`.

## شروط الحذف

يعيد الخادم فحص الارتباطات داخل معاملة مع قفل الموظف والسجل؛ المعاينة وحدها لا تمنح إذن الحذف لاحقًا إذا تغيرت البيانات.

السلفة المصروفة لا تحذف إلا بعد الإلغاء ووصول رصيدها للصفر. أي ارتباط بتصفية أو حركات تخص تصفية يمنع حذفها؛ تعالج التصفية الملغاة أولًا.

التصفية المعتمدة/المرحلة/المدفوعة يلزم إلغاؤها أولًا. يحظر حذفها عند وجود تخصيص مرحل، حركات سلف غير متوازنة لكل سلفة على حدة، أو دفعة دون مستند عكس مطابق للمبلغ.

تحذف تفاصيل التصفية وسجل إصداراتها وحجوزاتها ودفعاتها المعكوسة معها. تبقى حركة خصم السلفة والحركة العكسية في دفتر السلف، ويفصل ارتباطهما بالتصفية المحذوفة؛ الرصيد لا يتغير. بعد حذف التصفية يمكن حذف السلفة الملغاة نفسها مع حركاتها المعكوسة.

## النسخ الاحتياطي والتدقيق

قبل كل حذف تحفظ نسخة مشفرة من السجل وعلاقاته، بما فيها حركات السلف وبيانات المرفقات ومساراتها، داخل القرص الخاص `local` في `data-management/*.encrypted`. فشل حفظ النسخة يمنع الحذف. يحتفظ سجل التدقيق الدائم بالمدير والسبب والمرجع والموظف ومسار النسخة. ملفات المرفقات الخاصة تبقى للرجوع إليها ولا تُمحى مع سجلها.

هذه نسخة تخص السجل المحذوف، وليست نسخة كاملة من قاعدة البيانات عند كل حذف. الاستعادة من الحذف النهائي عملية صيانة تتطلب فك التشفير بواسطة مفتاح التطبيق، ثم التحقق من العلاقات والأرصدة قبل إعادة الإدخال؛ لا يوجد زر لاستعادة سجل محذوف نهائيًا. احتفظ بـ `APP_KEY` ونسخ قاعدة البيانات والمرفقات بأمان؛ لا يعاد توليد المفتاح عشوائيًا.

قبل تطبيق ترحيل الأرشفة على قاعدة التشغيل حُفظت نسخة SQLite كاملة متسقة في:
`storage/app/private/backups/before-data-management-20261022-043300.sqlite`.

لم ينفذ أي حذف لبيانات التشغيل أثناء التطوير؛ الاختبارات تستخدم قاعدة مؤقتة بالذاكرة أو قاعدة HTTP معزولة تحت `storage/framework/testing`.

## التحقق

- اختبارات الصلاحيات وتأكيد الحذف والنسخة المشفرة وفشل النسخ وتعديل الطلب وإعادة اعتماده ومنع تعديل المصروف.
- اختبارات حذف الحجوزات، منع حذف المعتمد، فحص عكس الدفعات، حفظ توازن دفتر السلف، حذف سلفة مصروفة بعد عكسها، والأرشفة واستعادة العرض.
- اختبار متصفح بواجهة HTTP حقيقية مع قاعدة معزولة لإنشاء طلب تجريبي ثم حذفه من الشاشة بعد كتابة التأكيد.

التشغيل بعد سحب التغييرات: `php artisan migrate` ثم بناء الواجهة بـ `node node_modules/vite/bin/vite.js build --configLoader native` داخل `frontend`.
