# معايير تطوير النظام

## الفصل المعماري

خدمات حساب المخالصات والإجازات والسلف مستقلة عن الهوية والمظهر. لا تضف إعدادًا يسمح بتغيير أساس السنة أو الأجر أو الاستحقاق أو تجاوز المراجعة والصرف. هذه قواعد أعمال ذات مسار تغيير واختبارات مستقلة.

المصدر المعتمد لتعريف الإعدادات الآمنة هو `config/system.php`. مصدر القيم التشغيلية هو `SystemSettingsService`، ثم قاعدة البيانات مع الرجوع إلى القيمة الافتراضية. لا تقرأ جدول الإعدادات مباشرة من Controllers أو Blade أو React، ولا تقرأ `.env` عبر API. إعدادات الاتصال والأسرار والجلسات والتخزين والبريد تبقى في config/env.

## Laravel

```php
$settings = app(\App\Services\SystemSettingsService::class);
$name = $settings->get('branding.name_ar');
$pageSize = $settings->pageSize();
$branding = $settings->reportBranding();
```

استخدم خدمة الإعدادات أو حقنها في المنشئ بدل تكرار الاستعلامات. تعديل القيم يمر عبر `update` لضمان التحقق والمعاملة وقفل الإصدار والتدقيق وإبطال Cache. لا تحدث الصفوف مباشرة ولا تقبل مفاتيح من العميل خارج السجل.

أي API جديد يحتاج صلاحيات خادم وسياسة نطاق الاطلاع. لا تعتمد على إخفاء زر React. صلاحية `manage-system-settings` محمية باستثناء صريح: admin لا يرثها، وdeveloper لا يرث صلاحيات مالية. إضافة صلاحية تشغيلية عادية تتم عبر `UserPermissions`؛ لا تضف صلاحية المطور إلى دليل صلاحيات المدير العادي.

التقارير تستخدم `reportBranding` و`exports.branding-style` أو تبني هوية مماثلة من الخدمة. مسار الشعار المحلي يخص توليد PDF فقط ولا يرجع في JSON الطباعة. اترك القيم المالية الدقيقة كما هي؛ إعداد المنازل العشرية للعرض والتصدير فقط.

## React والتصميم

```jsx
import { useSystemSettings } from '../system/SystemSettingsContext'
import { BrandLogo } from '../system/Brand'
const { settings } = useSystemSettings()
// <BrandLogo />
// <h1>{settings['branding.name_ar']}</h1>
```

استخدم `system-panel`, `system-input`, `system-button`, `system-button-primary`, `system-grid`, `system-stack` للمكونات الجديدة. القيم اللونية في CSS تأتي من `var(--color-primary)`, `--color-secondary`, `--color-accent`, `--color-background`, `--color-card`, `--color-text`, `--color-success`, `--color-warning`, `--color-error`. الخطوط من `--font-ar` و`--font-en`، والحواف من `--border-radius`.

لا تكتب اسم النظام أو ألوان hex داخل صفحات الأعمال. القيم الافتراضية فقط موجودة مركزيًا في `system/settings.js` للبدء قبل استجابة API. لوحة ألوان Tailwind القديمة موصولة بهذه المتغيرات في `applyTheme` حتى ترث الصفحات القائمة الهوية دون إعادة بنائها. `App.css` القديم غير مستورد؛ لا تعتمده لإنشاء مكونات جديدة.

استخدم `formatCurrency`, `formatNumber`, `formatDate`, `formatDateTime`, `todayForInput` بدل تنسيقات ثابتة داخل الصفحة. حافظ على حقول API للتواريخ بصيغة ISO وبأرقام لاتينية؛ تنسيق العرض لا يغيّر صيغة التخزين. اتجاه الواجهة موروث من Provider؛ لا تفرض `dir="rtl"` على صفحة أعمال جديدة إلا إذا كانت وثيقة عربية ثابتة الاتجاه لسبب واضح.

كل استدعاءات API تمر عبر `services/api.js`. الإعدادات العامة لا تحمل رمز مصادقة، والإدارة تحمل مصادقة المستخدم. لا تحفظ إعدادات المعاينة في localStorage؛ فقط الإعدادات العامة المحفوظة. عند مغادرة لوحة المطور يجب إلغاء المعاينة المؤقتة.

## الشعارات والملفات

لا تستخدم SVG يرفعه المستخدم أو أسماء ملفات أصلية. الرفع يقبل PNG/JPEG/WebP، يعيد ترميز الصورة إلى PNG، ويحفظ UUID في المسار الخاص. القيم المخزنة في سجل الإعدادات هي مراجع الأصول، وليست URLs عشوائية أو مسارات نظام ملفات. أبقِ الأصول القديمة للرجوع إليها ولا تحذف شعارًا بسبب فشل رفع بديله.

## الاختبار والتوسعة

أي إعداد جديد يحتاج اختبار الافتراضي والتحقق والحفظ وCache والصلاحية وتأثير عرضه. أي قناة تقرير جديدة تختبر الهوية دون تغيير الرصيد المالي. اختبر payload مزورًا ولا تكتفِ بالنقر في الواجهة. اختبارات المتصفح تستخدم قاعدة SQLite معزولة ولا تنشئ حساب مطور في بيانات التشغيل.

العزل الحالي على مستوى النسخة عبر `system.scope`. لا تأخذ scope من body أو query. لإضافة تعدد شركات مستأجرة مستقبلًا، أضف محلل نطاق موثوقًا إلى الخدمة وإلى مفتاح Cache ومسارات الأصول والصلاحيات؛ هذا المشروع لا يطبق تعدد المستأجرين حاليًا.
