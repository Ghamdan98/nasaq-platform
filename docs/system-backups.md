# النسخ الاحتياطي واختبار الاستعادة

## الإعداد الحالي

فُعّلت مهمة Windows باسم `Settlement-DailyBackup` يوميًا الساعة **02:00 بتوقيت الرياض**. تم تشغيلها تجريبيًا عبر مجدول Windows ونجحت، برمز خروج `0`.

تعمل المهمة بحساب المستخدم الحالي وبصلاحيات محدودة، ولا تظهر نافذة. إعداد `StartWhenAvailable` يسمح بتعويض الموعد الفائت عند توفر الجهاز. يجب أن يكون الجهاز يعمل وأن يكون المستخدم مسجل الدخول؛ يمكن قفل الشاشة. محاولة تفعيل التشغيل بعد تسجيل خروج المستخدم رفضتها صلاحيات Windows، لذلك تم الإبقاء على النمط المدعوم بدل طلب كلمة مرور أو تغيير صلاحيات النظام.

لدعم التشغيل أثناء تسجيل الخروج، يمكن لمسؤول Windows تشغيل المثبت في PowerShell بصلاحيات إدارية:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-backup-task.ps1 -RunWhenLoggedOff
```

الخيار يستخدم S4U للتخزين المحلي دون تخزين كلمة مرور. يحتاج توفر صلاحيات Windows الخاصة بتسجيل هذه المهمة.

أُضيف أيضًا جدول Laravel اليومي الساعة 02:00 بتوقيت الرياض للبيئات التي تستخدم `schedule:run`. **استخدم مجدول Windows الحالي أو مجدول Laravel، ولا تشغلهما معًا** لتجنب إنشاء نسختين متتاليتين. يوجد قفل ملفات يمنع التنفيذ المتزامن.

## محتويات النسخة

- نسخة SQLite متسقة بواسطة `VACUUM INTO`، بما في ذلك البيانات الموجودة في WAL، دون تعديل قاعدة التشغيل.
- ملفات التخزين الخاص والعام، بما فيها مرفقات السلف والنسخ المشفرة لسجلات الحذف النهائي.
- بيان SHA-256 وحجم لكل ملف، وعدد صفوف كل جدول.
- استثناء `storage/app/private/backups` القديم لمنع تضمين نسخ قواعد البيانات السابقة داخل كل نسخة جديدة.

النسخة ملف ZIP مشفر باستخدام AES-256، محفوظ خارج المجلد العام في:

`storage/app/backups/settlement-YYYYMMDD-HHMMSS-RANDOM.zip`

الاسم يحمل توقيت UTC؛ موعد المهمة اليومية بتوقيت الرياض. لا يحفظ النظام نسخًا غير مكتملة؛ أي فشل أثناء الإنشاء أو اختبار الاستعادة يلغي النسخة الجديدة فقط. تبقى النسخ السابقة دون حذف تلقائي. راقب مساحة القرص وضع سياسة احتفاظ مناسبة قبل تفعيل الحذف الدوري.

التشفير يعتمد على `APP_KEY` الأصلي. لا يتضمن الأرشيف ملف `.env` أو كلمة مرور قاعدة بيانات. احتفظ بنسخة آمنة منفصلة من إعدادات التطبيق ومفتاحه؛ تغيير المفتاح أو فقده يمنع فك النسخ. أسماء الملفات داخل ZIP تظهر كبيانات وصفية، لكن المحتويات والبيان مشفرة.

النسخ الحالية محلية على الجهاز نفسه. الحماية من تعطل القرص أو فقدان الجهاز تتطلب نسخ الأرشيفات وتقاريرها إلى وسيط أو وجهة خارج الجهاز، مع الاحتفاظ بالمفتاح منفصلًا. لم تضبط وجهة خارجية دون تحديدها.

## اختبار الاستعادة

بعد كل نسخة، يفك النظام **كل الملفات فعليًا** في مجلد مؤقت معزول، ويطابق أحجامها وSHA-256، ثم يفحص قاعدة البيانات:

- `PRAGMA integrity_check`.
- `PRAGMA foreign_key_check`.
- عدد الصفوف في جميع الجداول مقارنة ببيان النسخة.
- وجود المرفقات المسجلة في `advance_documents`.

لا تستبدل قاعدة التشغيل ولا المرفقات. تحذف الملفات المؤقتة بعد الفحص، ويحفظ تقرير خاص بجوار الأرشيف باسم `.zip.verified.json`، يحتوي وقت التحقق وبصمة الأرشيف والنتائج. عند الشك في تقرير قديم، أعد التحقق؛ بصمة التقرير تخص بايتات الأرشيف وقت الفحص.

الفحص له حد توسع افتراضي 5 GiB وحد أقصى 100 ألف ملف، ويمنع المسارات الخارجية والروابط الرمزية. يمكن تعديل حد الحجم في `config/backups.php` بعد توفير المساحة المطلوبة. هذه الخدمة تدعم SQLite والتخزين المحلي الحاليين؛ تغيير النظام إلى MySQL أو التخزين السحابي يتطلب تكييف آلية النسخ، والخدمة تتوقف برسالة واضحة بدل ادعاء نجاح نسخة ناقصة.

## الأوامر والسجلات

```powershell
# نسخة يدوية مع اختبار استعادة آلي
php artisan backup:run

# إعادة اختبار أحدث نسخة دون تعديل بيانات التشغيل
php artisan backup:verify

# اختبار نسخة محددة؛ اسم الملف فقط
php artisan backup:verify settlement-YYYYMMDD-HHMMSS-RANDOM.zip

# تسجيل أو تحديث مهمة Windows الحالية
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-backup-task.ps1

# قراءة آخر نتيجة وموعد التشغيل التالي
Get-ScheduledTaskInfo -TaskName Settlement-DailyBackup
```

السجلات: `storage/logs/backup-task.log` لمهمة Windows، وسجل Laravel لنتيجة النسخة. `LastTaskResult = 0` يعني النجاح، وأي رمز آخر يحتاج مراجعة السجل. لا توجد إشعارات بريدية خارجية مضبوطة.

## الاستعادة عند الحاجة

`backup:verify` اختبار فقط، ولا يعيد التشغيل إلى حالة قديمة. الاستعادة الفعلية تتم كإجراء صيانة: إيقاف الكتابة، حفظ نسخة من الحالة الحالية، اختيار نسخة اجتازت الفحص، فكها بمفتاح التطبيق الأصلي إلى مجلد منفصل، ثم استبدال قاعدة البيانات والمرفقات ضمن نافذة صيانة والتحقق من الأرصدة والدفعات والصلاحيات قبل إعادة الخدمة. لا تستبدل ملف SQLite أثناء تشغيل التطبيق أو تخلط ملف قاعدة مستعادًا مع ملفات WAL/SHM من قاعدة أخرى.

## التحقق المنفذ

نجح إنشاء نسخة من بيانات التشغيل، وفكها وفحص الجداول الـ34 والملفات التابعة. نجح التشغيل من مجدول Windows أيضًا. تغطي الاختبارات النسخ المشفر واستعادة ملفات التخزين الخاص والعام واستثناء النسخ القديمة ورفض المفتاح الخاطئ والمسارات الخارجية والنسخ المعدلة، مع بقاء بيانات التشغيل الأحدث دون تغيير.
