# فحص البنية قبل تنفيذ الإعدادات المركزية

فُحصت بنية Laravel/React والموديلات والخدمات ومسارات API وملفات config ومكونات العرض والتقارير، وقُرئت أسماء متغيرات البيئة فقط دون إخراج قيم الأسرار.

- الهوية ثابتة ومتباينة بين `AuthPage`, `AppSidebar`, `AppHeader`, الحاسبة والطباعة وBlade PDF؛ عنوان Vite ما زال عامًا. فرصة التحسين: سجل مركزي واحد يعاد استخدامه في جميع القنوات.
- الصفحات تعتمد على Tailwind بألوان blue/slate/emerald وغيرها، و`index.css` يحتوي قيمًا مباشرة للطباعة والخطوط. `App.css` ملف قديم غير مستورد. ستُربط لوحة ألوان Tailwind الحالية بالمتغيرات المركزية لتجنب إعادة بناء الصفحات أو تغيير منطقها.
- المصادقة Sanctum، والأدوار admin/hr/reviewer. المدير يمتلك جميع الصلاحيات تلقائيًا، وهو غير مناسب لصلاحية المطور المطلوبة. يلزم استثناء صريح وصلاحية محمية ودور developer منفصل، ومنع إدارة هذا الدور من لوحة المستخدمين العادية.
- الصلاحيات والخدمات المالية منفصلة، والحسابات معتمدة على المحركات الحالية. لن تتضمن إعدادات الهوية والمظهر أي معامل للأجور أو الإجازات أو القيود النظامية.
- قاعدة التشغيل SQLite والتخزين محلي؛ النسخ الكاملة مشفرة وتختبر استعادتها. يمكن شمول جدول الإعدادات وملفات الشعارات تلقائيًا ضمن الآلية الحالية.
- API عبر خدمة fetch مركزية، وتوجد رسائل خطأ وتدقيق Laravel؛ يمكن استخدامهما للإعدادات مع قفل وتدقيق وإبطال Cache.
- الواجهة عربية RTL مع نصوص ثابتة، وتنسيق المال SAR/ar-SA والتواريخ ثابت. إعداد اللغة سيضبط لغة المستند واتجاهه وتنسيق العرض؛ ترجمة نصوص الأعمال كافة تحتاج كتالوج ترجمة مستقل ويجب توثيق حدودها.
- تصدير PDF عبر mPDF، وExcel عبر PhpSpreadsheet/Maatwebsite، وصفحة طباعة React مستقلة. يجب توحيد هوية هذه القنوات مع الحفاظ على أرقام وحسابات الوثائق التاريخية.
- لا توجد خدمة بريد أعمال مرسلة حاليًا؛ يجب توفير قالب البريد وإعداد اسم المرسل مركزيًا للاستخدام المستقبلي، دون كشف SMTP أو إرسال رسائل أثناء التطوير.

القرار: سجل إعدادات مسموح فقط في `config/system.php`، جدول scoped للنسخة الحالية دون تنفيذ تعدد المستأجرين، خدمة إعدادات مركزية، سياسات وميدلوير للمطور، وTheme Provider مع Design Tokens، واختبارات API ومتصفح وتراجع الحسابات.
